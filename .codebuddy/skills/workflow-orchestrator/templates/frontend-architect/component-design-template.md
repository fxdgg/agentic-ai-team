## 使用说明

## 组件拆分原则

### 拆分判断标准

| 信号 | 判断 | 行动 |
|------|------|------|
| 同一段 UI 在 2 个以上页面出现 | 高复用 | 提取为全局组件 `src/components/` |
| 页面内一个区块逻辑独立、可独立测试 | 内聚性 | 提取为页面子组件 `pages/{page}/components/` |
| 组件代码超过 200 行 | 过度复杂 | 拆分为更小的子组件 |
| JSX 嵌套超过 3 层 | 可读性差 | 提取内层为子组件 |
| 某段逻辑在多个 Hooks 中重复 | 逻辑复用 | 提取为全局 Hook `src/hooks/` |

### 组件层级定义

```
组件层级：
├── 全局基础组件（src/components/ui/）
│   └── 对 AntD/原生组件的二次封装，全项目通用
├── 全局业务组件（src/components/business/）
│   └── 特定业务域的通用组件（如 GoodsCard、OrderStatus）
├── 页面子组件（src/pages/{page}/components/）
│   └── 仅在该页面内使用的组件
└── 临时组件
    └── 不建议创建，应归入上述三层之一
```

## 组件设计规范

### Props 设计规范

| 规则 | 说明 |
|------|------|
| 必要 Props 不加 `?` | 缺少时组件无法正常工作的 Props 必须为必填 |
| 回调函数以 `on` 开头 | 如 `onClick`、`onChange`、`onSubmit` |
| 布尔类型以 `is/has/show` 开头 | 如 `isLoading`、`hasError`、`showFooter` |
| 复杂类型独立定义 | 不在 Props 接口中内联定义复杂对象类型 |
| 扩展 Props 使用 `Omit/Pick` | 基于基础组件 Props 扩展时，显式标注继承关系 |

### 组件状态管理

| 状态类型 | 管理方式 | 示例 |
|----------|----------|------|
| UI 状态（展开/收起） | 组件内部 `useState` | 下拉菜单展开状态 |
| 表单状态 | 父组件通过 Props 控制 | 受控表单 |
| 异步数据 | Hooks 提供，通过 Props 传入 | 列表数据、加载状态 |
| 全局共享状态 | Zustand Store | 用户信息、购物车 |
