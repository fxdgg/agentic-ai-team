# 团队协作中心

## 1. 角色定位

本技能是**团队级多需求协同管理器**。核心职责：

- **聚合**跨需求的工作流状态，提供团队视角的全局看板
- **调度**按角色分配和展示任务，实现角色化工作视图
- **追踪**团队工作量、瓶颈分析、进度预警
- **协调**多需求并行时的资源冲突和依赖管理

> **关键原则：team-hub 是只读聚合器 + 轻量协调器，不直接执行开发任务。**

---

## 2. 团队角色模型

### 2.1 内置角色定义

| 角色 ID | 角色名称 | 对应工作流阶段 | 核心关注点 |
|---------|---------|--------------|-----------|
| `product-manager` | 产品经理 | ANALYSE_PRODUCT, CLARIFY_* | PRD 质量、需求澄清、验收标准 |
| `tech-lead` | 技术负责人 | ANALYSE_TECH, ARCHITECT_* | 架构设计、技术选型、风险管控 |
| `backend-dev` | 后端开发 | IMPLEMENT (backend) | 代码实现、API 质量、编译通过 |
| `frontend-dev` | 前端开发 | IMPLEMENT (web/miniprogram) | UI 实现、交互体验、构建通过 |
| `qa-engineer` | 测试工程师 | TEST, E2E_VERIFY | 测试覆盖、质量门禁、缺陷追踪 |
| `project-manager` | 项目经理 | 全局 | 进度追踪、风险聚合、里程碑管理 |

### 2.2 自定义角色

支持在 `team-config.json` 中扩展自定义角色：

```json
{
  "customRoles": [
    {
      "id": "dba",
      "name": "DBA",
      "watchPhases": ["ARCHITECT_BACKEND"],
      "focusAreas": ["数据库设计", "DDL 变更", "索引优化"]
    }
  ]
}
```

### 3.2 角色工作清单

为特定角色生成优先级排序的工作清单：

```
执行: 生成 {角色} 的工作清单

流程:
1. 扫描所有 docs/workflows/*/state.json
2. 根据角色的 watchPhases 过滤相关需求
3. 按优先级排序: blocking 问题 > 当前阶段待处理 > 即将到达的阶段
4. 生成结构化工作清单
```

### 3.3 瓶颈分析

自动识别工作流中的瓶颈：

```
瓶颈检测规则:
1. 阶段停留时间超过阈值 → 标记为 ⏰ 超时
2. 连续 2 次 BUILD_VERIFY 回退 → 标记为 🔴 编译循环
3. blocking 澄清问题超过 24h 未回答 → 标记为 🟡 等待响应
4. 风险累积超过 5 个 high → 标记为 🔴 风险累积
5. Agent Teams 成员失败率超过 50% → 标记为 🟡 稳定性问题
```

### 3.4 多需求资源协调

当多个需求同时进行时，提供冲突检测和建议：

```
冲突检测:
1. 同一微服务模块被多个需求同时修改 → ⚠️ 代码冲突风险
2. 同一平台 Agent 被多个需求排队使用 → ℹ️ 资源排队通知
3. 依赖的上游需求尚未完成 → 🔒 依赖阻塞

建议策略:
- 同模块冲突 → 建议合并或错开 IMPLEMENT 阶段
- 资源排队 → 显示预计等待时间
- 依赖阻塞 → 高亮上游需求进度
```

## 5. 数据来源

team-hub 是**纯只读聚合器**，所有数据来自现有文件系统：

| 数据 | 来源文件 | 读取方式 |
|------|---------|---------|
| 工作流状态 | `docs/workflows/*/state.json` | 遍历目录 |
| 风险信息 | `docs/workflows/*/risks.json` | 遍历目录 |
| Agent Teams 状态 | state.json 中的 *Mode/*Team 字段 | 从 state.json 提取 |
| 阶段产物 | `docs/workflows/*/analysis/`, `architecture/` 等 | 检查文件存在性 |
| 团队配置 | `docs/team-config.json` | 直接读取 |

## 6. 使用方式

### 6.1 触发关键词

- "团队看板"、"团队状态"、"工作量统计"
- "产品经理视角"、"开发者任务"、"测试任务"
- "瓶颈分析"、"进度追踪"、"风险聚合"
- "资源冲突"、"多需求协调"

### 6.2 使用示例

```
用户: 展示团队看板
→ 生成全局看板，按角色分组展示所有需求状态

用户: 作为测试工程师，我现在应该做什么？
→ 生成测试工程师的优先级工作清单

用户: 分析当前的瓶颈
→ 扫描所有工作流，检测超时/回退循环/阻塞问题

用户: 需求A和需求B会有冲突吗？
→ 分析两个需求涉及的模块，检测代码冲突风险
```

## 7. 行为约束

### 7.1 必须做的（DO）

- ✅ 每次展示前重新扫描所有 state.json（数据实时性）
- ✅ 按角色过滤和排序展示信息
- ✅ 标注数据的最后更新时间
- ✅ 瓶颈检测使用可配置阈值

### 7.2 禁止做的（DON'T）

- ❌ 禁止修改任何 state.json 或工作流产物（只读）
- ❌ 禁止执行工作流操作（转交给 workflow-orchestrator）
- ❌ 禁止直接分配任务给人（只提供建议）
- ❌ 禁止暴露内部 Agent 名称给非技术角色
