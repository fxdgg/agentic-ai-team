# AI Team — 产品需求文档 (PRD)

> 版本：v0.1 | 更新日期：2026-03-24

---

## 一、产品定位

**AI Team** 是面向团队管理者的 AI 工程交付操作系统（Agentic Delivery OS）。核心价值：让 5-10 人的小团队管理和协调 100 个 AI Agent，实现需求的全流程自动化交付。

## 二、目标用户

| 用户角色 | 使用场景 | 核心诉求 |
|---------|---------|---------|
| 技术负责人/架构师 | 管理需求交付全局、做架构决策 | 全局可观测、风险早发现、决策有上下文 |
| Capability Owner | 管理自己域内的 Agent、审批升级项 | 快速响应审批、掌握域内进度、降低认知负载 |
| 项目经理/TPM | 跟踪需求进度、评估交付健康度 | 数据驱动、进度透明、瓶颈可定位 |

## 三、核心功能模块

### 3.1 交付总览（默认首页）

**用户故事**：作为技术负责人，我希望打开 Dashboard 就能一眼看到所有需求的交付进度、当前风险和阻塞项，以便快速判断是否需要干预。

**功能规格**：
- 4 个核心指标卡片：需求总数、进行中、已完成、阻塞数（含趋势箭头）
- 需求列表表格：名称、当前阶段进度条、Owner、健康度徽章、SLA 倒计时
- 阶段分布环形图：展示各阶段的需求数量分布
- 风险热力图：按严重度 × 模块的交叉矩阵
- 最近回滚时间线：最近 5 条回退事件，含回退原因和修复状态

**验收标准**：
- [ ] 指标卡片数据实时更新（WebSocket 推送，延迟 < 2s）
- [ ] 点击需求可跳转到工作流详情页
- [ ] 风险热力图支持按严重度筛选
- [ ] 页面首次加载时间 < 1.5s

### 3.2 Agent 协作看板

**用户故事**：作为技术负责人，我希望看到所有 Agent 的运行状态、任务耗时和失败率，以便评估 Agent 效能并做优化决策。

**功能规格**：
- Agent 统计卡片：总数/活跃/空闲/失败
- Agent 卡片列表：名称、角色标签、当前任务、Owner 头像、状态灯
- 协作 Sankey 图：阶段间 Agent 的 handoff 关系和返工率
- Agent 效能排行表：首次通过率、平均耗时、token 消耗

**验收标准**：
- [ ] Agent 状态灯实时变化
- [ ] Sankey 图可交互，悬停显示返工率数值
- [ ] 排行表支持多维排序
- [ ] token 消耗统计准确到千位

### 3.3 决策中心

**用户故事**：作为 Capability Owner，我希望在一个地方看到所有待我处理的决策和审批项，以便快速响应不阻塞工作流。

**功能规格**：
- 待决策数量徽章 + 紧急程度筛选器
- 决策卡片流：标题、上下文摘要、批准/拒绝/暂缓按钮、关联工作流链接
- ADR 列表（可折叠）：历史架构决策记录
- 决策统计饼图：风险接受 / 拒绝 / 暂缓分布

**验收标准**：
- [ ] 新决策到达时有浏览器通知
- [ ] 批准/拒绝操作后卡片立即移出队列
- [ ] ADR 支持关键字搜索
- [ ] 审批操作需二次确认

### 3.4 人机映射视图

**用户故事**：作为技术负责人，我希望直观看到每个团队成员名下的 Agent 分配和审批积压，以便及时发现瓶颈并均衡负载。

**功能规格**：
- 团队成员卡片列表：头像、姓名、能力域标签、负载进度条
- Agent 树状图：选中成员后展示名下所有 Agent 及各自当前状态
- 审批积压列表 + 响应时间趋势图
- 瓶颈告警区域：高亮过载 Owner

**验收标准**：
- [ ] 负载进度条颜色随负载级别变化（绿/黄/红）
- [ ] 点击 Agent 可跳转到 Agent 详情
- [ ] 瓶颈检测算法：审批积压 > 5 或平均响应时间 > 4h 触发告警
- [ ] 支持拖拽重新分配 Agent 到不同 Owner

### 3.5 质量与学习中心

**用户故事**：作为技术负责人，我希望看到缺陷模式趋势和规则改进效果，以便持续优化 AI 工程流水线的质量。

**功能规格**：
- 质量趋势折线图：首次通过率、回滚率、缺陷泄漏率（按周统计）
- 缺陷模式热力图：Agent 类型 × 缺陷类型
- 进化日志列表：pending/applied/rejected 三个 Tab
- 规则改进效果对比卡片：改进前后指标对照

**验收标准**：
- [ ] 趋势图支持自定义时间范围
- [ ] 进化日志可直接审阅操作（接受/拒绝/暂缓）
- [ ] 规则改进前后数据通过 A/B 对照展示
- [ ] Agent 可信度排行基于多维评估结果

## 四、通用工作流引擎

### 4.1 工作流配置

- 通过 YAML 文件定义工作流模板
- 支持阶段依赖（DAG）和线性状态机
- 每个阶段可配置：Agent 角色、三步模式、澄清开关、质量门禁
- 支持回退目标、最大回退次数

### 4.2 三步模式协议

每个阶段遵循标准生命周期：
1. **预览（Preview）**：展示即将执行的计划和涉及的 Agent
2. **执行（Execute）**：调度 Agent 执行任务，收集产物
3. **总结确认（Summary）**：展示执行结果，用户确认后推进

### 4.3 质量门禁

- 每个阶段完成后可选质量门禁检查
- 三级结果：PASS / WARN / FAIL
- FAIL 阻断推进，需回退或人工介入

## 五、Agent 管理

### 5.1 Agent 注册表

- 每个 Agent 通过 YAML 文件定义
- 字段：名称、角色、能力标签、适用阶段、Prompt 模板
- 支持版本管理

### 5.2 Agent 调度

- 按阶段自动匹配最适合的 Agent
- 支持优先级调度和并行调度
- Token 预算控制：Agent 执行前检查预算余量
- 失败重试策略：自动重试 1 次后升级到 Owner

## 六、人机映射模型

### 6.1 Capability Owner 模型

```
Team Member (人)
  └── Capability Domain (能力域)
        └── Agent Definition (Agent 定义)
              └── Agent Run (执行实例)
```

- 一个人可以拥有多个能力域
- 一个能力域可以挂载多个 Agent
- Agent 遇到阻塞自动路由到对应 Owner

### 6.2 升级策略

| 触发条件 | 升级目标 | 超时处理 |
|---------|---------|---------|
| Agent 执行失败 | 对应能力域 Owner | 4h 无响应升级到技术负责人 |
| 质量门禁 FAIL | 对应能力域 Owner | 8h 无响应升级到技术负责人 |
| 需要人工决策 | 对应能力域 Owner | 2h 无响应通知全团队 |

## 七、非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | Dashboard 首屏 < 1.5s，API 响应 < 200ms |
| 并发 | 支持 50 个并行工作流，100 个并行 Agent |
| 可用性 | 99.9% SLA |
| 安全 | 所有决策留痕，Agent 执行结果不可变 |
| 审计 | 全链路操作日志，支持按时间/人员/工作流筛选 |
