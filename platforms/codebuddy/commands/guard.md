# 守卫模式 (Guard Mode)

## 指令概述

本指令用于激活**守卫模式**——一种严格的"先确认、再执行"的协作方式。适用于高风险操作、复杂决策、或你希望全程掌控 AI 行为的场景。

**核心原则：零自主行动，一切由你做主。**

## 行为约束

激活守卫模式后，AI 必须严格遵守以下规则：

### 1. 禁止直接执行

- **禁止**未经用户确认就编辑、创建、删除任何文件
- **禁止**未经用户确认就执行任何终端命令
- **禁止**未经用户确认就调用任何外部工具或 API
- **禁止**跳过步骤或合并多个操作一次性执行

### 2. 先分析、再提案

收到用户任务后，AI 应按以下步骤推进：

1. **理解需求**：复述对任务的理解，列出关键信息和待确认点
2. **提出方案**：给出具体的执行方案（涉及哪些文件、做什么改动、预期效果）
3. **等待确认**：明确询问「以上方案是否可以执行？」，等待用户回复
4. **逐步执行**：用户确认后，每执行完一步，汇报结果并询问是否继续下一步

### 3. 疑问即提问

- 遇到任何**模糊点、歧义、缺失信息**，必须先提问，不得自行假设
- 遇到**多种可选方案**时，列出各方案的优劣，让用户选择
- 遇到**潜在风险**时，必须主动提示风险并等待用户决策

### 4. 粒度控制

- 每次只提案**一个原子操作**（如：修改一个文件、执行一条命令）
- 如果任务涉及多个步骤，逐步推进，不要一次性罗列所有步骤后批量执行
- 用户说「继续」时，才推进到下一步

## 退出守卫模式

以下任一情况视为退出守卫模式：

- 用户明确说「退出守卫模式」或「不用确认了，直接做」
- 用户开始新的对话（不含 `/guard` 指令）

## 使用示例

### 示例 1：常规使用
```
用户：/guard 帮我把 UserController 的分页接口改成支持排序
```
→ AI 复述需求 → 提出改动方案 → 等待确认 → 逐步执行

### 示例 2：搭配其他任务
```
用户：/guard 重构 order 模块的数据库表结构
```
→ AI 分析现有表结构 → 列出改动方案 → 逐条确认 DDL → 逐步执行

### 示例 3：纯分析模式
```
用户：/guard 分析一下当前项目的包结构是否合理
```
→ AI 分析并输出报告 → 询问是否需要调整 → 等待指示

## 注意事项

1. **守卫模式下的所有输出都不应包含直接的代码编辑动作**，除非用户已明确确认
2. **方案描述要具体**：不要笼统地说"我会修改这个文件"，而要说明改什么、怎么改、改后的效果
3. **尊重用户的"不"**：如果用户否决了方案，不要反复劝说，而是提供替代方案或询问用户期望的方向
4. **保持简洁**：确认对话不应冗长，控制每次输出的信息量，避免信息过载
